# راهنمای آزمون نسخه پیش از APK

## هدف

این نسخه، آخرین نسخهٔ قابل استفاده در مرورگر و نصب به‌عنوان PWA پیش از ورود به مرحلهٔ APK است. لطفاً قبل از تبدیل به APK، برنامه را با اطلاعات واقعی کارگاه در چند روز کاری استفاده کنید تا خطاهای محاسباتی، نیازهای جدید و نقاط ابهام رابط کاربری مشخص شوند.

## روش استفاده پیشنهادی

نسخهٔ عمومی را در Chrome گوشی باز کنید، از منوی مرورگر گزینهٔ **افزودن به صفحهٔ اصلی / نصب برنامه** را انتخاب کنید و سپس برای کارهای روزمره از همان نسخهٔ نصب‌شده استفاده کنید. داده‌ها در حافظهٔ محلی همان مرورگر و دستگاه ذخیره می‌شوند؛ حذف داده‌های مرورگر یا پاک‌کردن برنامه بدون داشتن فایل پشتیبان می‌تواند داده‌ها را از بین ببرد.

## سناریوهای ضروری آزمون

| حوزه | اقدام پیشنهادی | نتیجه‌ای که باید کنترل شود |
|---|---|---|
| طرف حساب | یک مشتری و یک تأمین‌کننده با چند نقش ثبت کنید | ویرایش کامل، حذف و نمایش نقش‌ها درست باشد |
| کالا و انبار | کالا را در انبار مواد اولیه و محصول ثبت کنید | واحد اول، واحد دوم، نسبت تبدیل و موجودی درست باشد |
| فاکتور | فروش با واحد دوم، تخفیف و تاریخ شمسی ثبت کنید | تعداد پایه، قیمت، مبلغ نهایی و شماره پیشنهادی درست باشد |
| FIFO | چند فاکتور قدیمی و چند چک با سررسیدهای متفاوت ثبت کنید | تخصیص از قدیمی‌ترین فاکتور و نزدیک‌ترین سررسید انجام شود و فاکتور بیشتر از ۱۰۰٪ تسویه نشود |
| چک | وضعیت‌های نزد ما، وصول، برگشتی، عودت و جایگزین را امتحان کنید | مرجع حساب، رنگ ردیف، تخصیص و بازسازی FIFO هماهنگ باشد |
| تولید | فرمول با مواد اولیه و سربار ثبت کنید | مصرف مواد، ورود محصول و بهای تولید درست باشد |
| گزارش | دفتر چک، دفتر فاکتور، بستن ماه، Aging و صورت‌حساب را بررسی کنید | تاریخ شمسی، مانده، سود دیرکرد و ردیف‌های باطل درست باشند |
| پشتیبان | قبل و بعد از چند عملیات فایل JSON بگیرید | تاریخ/شمارش نسخه تغییر کند و همهٔ مجموعه‌ها در فایل باشند |
| بازیابی | یک فایل پشتیبان را در مرورگر دیگر با ورود دستی JSON بازیابی کنید | داده‌ها بدون تداخل و با قالب جدید خوانده شوند |
| Drive | اتصال و ذخیرهٔ یک نسخهٔ پشتیبان را امتحان کنید | فایل جدید با نام نسخه‌دار در پوشهٔ پروژه ایجاد شود |
| Undo/Redo | چند ثبت، ویرایش و حذف انجام دهید | برگشت و جلو رفتن مرحله‌ای و بدون از دست رفتن داده انجام شود |
| موبایل | صفحات بانک، پشتیبان، تولید و گزارش را در عرض کم بررسی کنید | اسکرول افقی ناخواسته و خروج متن از کادر وجود نداشته باشد |

## مواردی که باید گزارش شوند

برای هر ایراد، تاریخ شمسی، صفحه، اقدام انجام‌شده، نتیجهٔ مورد انتظار، نتیجهٔ واقعی و تصویر یا فایل پشتیبان مرتبط را ثبت کنید. برای اختلاف عددی، مبلغ‌ها را به تومان و با ذکر شمارهٔ فاکتور/چک ارسال کنید.

## محدودیت‌های شناخته‌شده پیش از APK

نسخهٔ فعلی local-first است و دسترسی امن مشتری به حساب خودش ندارد. فایل پشتیبان باید به‌صورت دستی مدیریت شود و توکن Drive به مرورگر وابسته است. ایجاد پرتال مشتریان، احراز هویت سمت‌سرور، Row Level Security و همگام‌سازی چنددستگاهی امن باید قبل از انتشار محصول چندکاربره انجام شود؛ تبدیل مستقیم نسخهٔ استاتیک فعلی به APK این محدودیت امنیتی را حل نمی‌کند.

## معیار ورود به مرحلهٔ APK

پس از یک دورهٔ استفادهٔ واقعی و رفع ایرادهای گزارش‌شده، باید موارد زیر بدون خطای بازتولیدشونده تأیید شوند: تخصیص FIFO، بستن ماه، موجودی و تولید، پشتیبان و بازیابی، صفحات موبایل، گزارش‌های مالی، نصب PWA و عدم از دست رفتن داده پس از به‌روزرسانی. سپس دربارهٔ بسته‌بندی APK، سیاست به‌روزرسانی و انتخاب معماری backend تصمیم‌گیری می‌شود.
