# راهنمای آزمون‌ها و صحه‌گذاری (Testing & Quality Assurance)

این سند روش اجرای آزمون‌های سامانه، شرح فایل‌های فیکسچر، اسکریپت‌های صحه‌گذاری و معیارهای پذیرش تغییرات را مشخص می‌کند.

---

## ۱. نحوهٔ اجرای آزمون‌ها (Running Tests)

در محیط ترمینال مخزن توسعه، آزمون‌ها با دستورات زیر اجرا می‌شوند:

```bash
# اجرای کل ۹۵ تست واحد و یکپارچه به صورت کامل:
npx vitest run

# بررسی خطاهای تایپ‌اسکریپت و صحت انواع:
npm run lint

# بررسی کامپایل و بیلد کامل تولیدی:
npm run build
```

---

## ۲. ساختار فیکسچرها و داده‌های آزمایشی (Fixtures & Checksums)

برای جلوگیری از اتکا به داده‌های خصوصی و اطمینان از تکرارپذیری، یک فیکسچر کامل عملیاتی با مقادیر شناخته‌شده در مخزن نگهداری می‌شود:
- **فایل فیکسچر:** `client/src/lib/fixtures/price-unit.fixture.ts`
- **چک‌سام معتبر فیکسچر:** `docs/PRICE-UNIT-FIXTURE-CHECKSUM.json`  
  مقدار قطعی هش SHA-256: `26c49b391cd15725a6ea1a3e92fb2cc6717fbf8f0831aa3a4b377484c35af4d5`
- سناریوی فیکسچر شامل: ماده اولیه، قطعه خروجی، اجرای تولید ۱۰ عدد، صدور فاکتور فروش، دریافت چک با سررسید، محاسبهٔ تأخیر و خروجی/ورودی پشتیبان است.

---

## ۳. اسکریپت‌های تشخیصی تخصصی (Diagnostic Probes & Scripts)

در پوشهٔ `/scripts` ابزارهای مستقلی برای تحلیل‌های مرزی تعبیه شده‌اند:

1. **`scripts/audit-harness.ts`:**  
   آزمون جامع ۶۰۶ حالت مختلف ترکیب فاکتورها، مبالغ، تخفیف‌ها، پله‌های سود و وضعیت‌های چک جهت اطمینان از عدم وجود استثناهای پیش‌بینی‌نشده.
2. **`scripts/audit-jalali-picker.ts`:**  
   پیمایش روز به روز در ۳۰۱ سال گاه‌شماری هجری خورشیدی برای تطبیق ۱۰۰٪ الگوریتم تقویم UI با محاسبات رسمی نجومی کبیسه.
3. **`scripts/currency-dry-run.ts`:**  
   ابزار بررسی تشخیصی ۲۲ فیلد مالی دیتابیس بدون دست‌کاری و مقایسهٔ چک‌سام برای تضمین پایداری مبالغ در فرآیندهای بازخوانی.
4. **`scripts/test-fifo.ts`:**  
   شبیه‌سازی سناریوهای پیچیدهٔ چند فاکتوری و چند چکی برای صحه‌گذاری تقدم و تأخر زمانی تسویه و محاسبهٔ اصل و دیرکرد.

---

## ۴. چک‌لیست تأیید هر تغییر جدید (Definition of Done)

پیش از آنکه هرگونه تغییر در کد کامل تلقی شود، موارد زیر باید محقق شده باشند:
- [ ] اجرای `npx vitest run` با موفقیت ۱۰۰٪ تست‌ها بدون شکست (Failure).
- [ ] اجرای `npm run lint` (`tsc --noEmit`) با خطای صفر.
- [ ] اجرای `npm run build` بدون ارور ساخت.
- [ ] عدم دست‌کاری یا تغییر در مبالغ فاکتورها یا چک‌های گذشته.
- [ ] حفظ کامل سازگاری با فایل‌های بکاپ نسخهٔ قبلی (`Backward Compatibility`).
- [ ] ثبت تغییرات در `CHANGELOG.md` و عنداللزوم در `DECISION-LOG.md` یا `BUGS.md`.
