# راهنمای بازیابی اضطراری پروژه

این راهنما برای حالتی است که حساب کاربری تعلیق شود، چت‌ها در دسترس نباشند، Google Drive موقتاً مجوز ندهد یا دادهٔ مرورگر از بین برود.

## اصل مهم

تعلیق حساب به‌خودی‌خود نباید باعث توقف پروژه شود، به شرط آن‌که کد، مستندات و بکاپ داده خارج از چت نگهداری شده باشند. این راهنما محتوای حساب تعلیق‌شده را جعل یا حدس نمی‌زند؛ فقط مسیر بازیابی دارایی‌های مستقل را تعریف می‌کند.

## ترتیب منابع

۱. GitHub: `rasool083/accounting-workshop-pwa`  
۲. پوشهٔ `docs/` همان مخزن  
۳. آخرین JSON معتبر روی دستگاه یا فضای مستقل  
۴. نسخه‌های زمان‌دار Google Drive  
۵. Google Sheets پروژه  
۶. `rasool083/Accounting-` برای تاریخچه و مقایسه

## بازیابی کد

```bash
gh repo clone rasool083/accounting-workshop-pwa
cd accounting-workshop-pwa
git log --oneline --decorate -20
git status --short
pnpm install --frozen-lockfile
pnpm check
pnpm build
```

اگر GitHub در دسترس نبود، باید از یک clone محلی یا archive مستقل استفاده شود. هیچ فایل ناشناخته‌ای بدون بررسی `git diff` و checksum جایگزین شاخهٔ کاری نشود.

## بازیابی داده

۱. آخرین فایل JSON را با نام، تاریخ، حجم، commit و checksum ثبت کنید.
۲. ساختار، نسخهٔ backup و وجود آرایه‌های اصلی را بررسی کنید.
۳. فایل را ابتدا در محیط یا مرورگر جدا restore کنید.
۴. تعداد طرف حساب، کالا، فاکتور، چک، تراکنش و فرمول تولید را با گزارش اولیه مقایسه کنید.
۵. نمونه‌های FIFO، تبدیل واحد، جمع فاکتور و موجودی را اجرا کنید.
۶. فقط پس از موفقیت، فایل را در محیط کاری وارد کنید.

هرگز بکاپ را مستقیماً با copy روی localStorage یا فایل اصلی تولیدی جایگزین نکنید.

## حداقل کنترل بعد از restore

- جمع مبلغ ریزاقلام با مبلغ فاکتور؛
- تطبیق `quantityBase` با ضریب تبدیل فعلی؛
- نبودن party/product/account/warehouse orphan؛
- تخصیص نشدن بیش از مبلغ چک؛
- بررسی فاکتورهای باطل و وضعیت چک‌ها؛
- کنترل موجودی کالاهای تولیدی و مواد اولیه؛
- بازشدن همهٔ صفحات اصلی؛
- خروجی گرفتن از یک بکاپ جدید پس از restore موفق.

## بازیابی وقتی Drive مجوز ندارد

اگر مجوز Google Drive در مرورگر موجود نبود، از گزینهٔ خروجی/بازیابی محلی استفاده کنید. فایل Drive را از یک دستگاه مجاز دانلود کنید و پس از بررسی checksum از بازیابی دستی متن JSON استفاده کنید. اطلاعات OAuth یا Client Secret نباید در فایل backup یا Git قرار گیرد.

## بازیابی تاریخچهٔ تصمیم‌ها

پس از clone، این فایل‌ها را به‌ترتیب بخوانید:

```text
docs/PROJECT-CONTINUITY.md
docs/CHAT-CONTINUITY-PROTOCOL.md
docs/DECISION-LOG.md
docs/CHANGELOG.md
docs/PROJECT-REFERENCE.md
```

آخرین ورودی `DECISION-LOG.md` وضعیت تصمیم‌ها و ریسک‌های باز را مشخص می‌کند. اگر بین مستندات و کد اختلاف بود، اختلاف باید ثبت شود و بدون تصمیم صریح قرارداد مالی تغییر نکند.

## بعد از بازگشت حساب

بازگشت حساب، جایگزین نسخه‌های مستقل نیست. باید commitهای حساب، فایل‌های Drive و وضعیت فعلی مخزن مقایسه شوند. هر اختلاف در یک issue یا ورودی دفتر تصمیم ثبت شود. اطلاعات خصوصی یا credentialهای منتشرشده باید چرخش داده شوند.

## برنامهٔ پشتیبان دوره‌ای

برای هر milestone، یک commit پایدار، یک فایل JSON، یک checksum و یک یادداشت restore آزمایشی نگهداری شود. نسخهٔ دوم باید خارج از همان سرویس باشد. نام پیشنهادی فایل:

```text
accounting-workshop-backup-YYYY-MM-DD-commit-<short-sha>.json
```

این راهنما فقط زمانی مؤثر است که نسخه‌های مستقل واقعاً ایجاد و آزمایش شوند.
