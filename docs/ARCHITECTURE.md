# معماری سامانه (System Architecture)

## ۱. نمای کلان معماری (High-Level Overview)

نرم‌افزار «حسابداری کارگاه» بر پایهٔ الگوی **Local-First Single Page Application (SPA)** با اکوسیستم مدرن زیر پیاده‌سازی شده است:
- **هستهٔ رابط کاربری:** React 19 + TypeScript 5.6
- **فریم‌ورک کامپوننت و استایل:** Tailwind CSS v4 + مجموعه کامپوننت‌های Radix UI / shadcn
- **محیط ساخت و توسعه:** Vite 7 (سازگار با محیط ابری توسعه روی پورت ۳۰۰۰ و هاست `0.0.0.0`)
- **مدیریت تاریخ خورشیدی:** کتابخانهٔ مستقل گاه‌شماری جلالی بر مبنای محاسبات تقویمی نجومی و `Intl`
- **پوستهٔ نیتیو موبایل:** Capacitor 8 با ساختار کامل پروژهٔ اندروید در `/android` و شناسهٔ `ir.workshop.accounting`
- **استقرار رسمی:** استقرار استاتیک از طریق GitHub Pages و اکشن‌های GitHub

## ۲. اصل تفکیک لایه‌ها: RAW / MASTER / CALC / APP

به منظور جلوگیری از درهم‌تنیدگی داده‌های خام، پرونده‌های پایه، محاسبات پیچیده و منطق نمایش، سیستم ساختار تفکیک‌شدهٔ زیر را حفظ می‌کند:

```
┌─────────────────────────────────────────────────────────────┐
│                 APP / UI Presentation Layer                 │
│  (React Components, Forms, Tables, Dialogs, Print Media)   │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────▼──────────────────────────────┐
│                  CALC / Projections Layer                   │
│   (FIFO Engine, Delay Cost, Ledger Projections, Unit        │
│    Conversions, Effective Profit, Integrity Audits)         │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────▼──────────────────────────────┐
│                    MASTER Data Records                      │
│   (Products, Units, Formulas, Accounts, People, Rules)      │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────▼──────────────────────────────┐
│                     RAW Event Ledger                        │
│   (InventoryEvents, CashEvents, PartnerObligationEvents,    │
│    Raw Invoices, Raw Transactions, Raw Checks)              │
└─────────────────────────────────────────────────────────────┘
```

### ۱. لایهٔ داده‌های خام و رویدادی (RAW Event Layer)
- تراکنش‌های ایجادشده در لحظهٔ وقوع بدون دست‌کاری تاریخی:
  - `inventoryEvents`: تمام تغییرات فیزیکی موجودی (ورود خرید، مصرف تولید، خروج فروش، اصلاحات انبار، ابطال و reversal).
  - `cashEvents`: گردش‌های نقدی و بانکی (دریافت، پرداخت، انتقال، کارمزد، وصول/برگشت چک، reversal).
  - `partnerObligationEvents`: رخدادهای مرتبط با تعهدات شرکای تجاری.
  - فاکتورهای ثبت‌شده و پرداختی‌های فاکتور خرید (`purchasePayments`).

### ۲. لایهٔ پرونده‌های پایه (MASTER Data Layer)
- موجودیت‌های تعریفی و مرجع سیستم:
  - `products`: کالاها و مواد اولیه، ضرایب تبدیل واحد پایه و واحد دوم.
  - `warehouses`: انبارهای کارگاه.
  - `productionFormulas`: فرمول‌های تولید قطعه و بسته‌های تولیدی (BOM).
  - `accounts`: حساب‌های بانکی، صندوق‌ها و سرفصل‌های نقدی.
  - `people`: اشخاص (مشتری، تأمین‌کننده، شریک، کارگر، کارمند) و نقش‌های چندگانه.
  - `paymentRules`: شرایط پرداخت و پله‌های درصد سود دیرکرد.
  - `priceHistory`: تعرفه‌های قیمتی بر مبنای واحد پایه.
  - `settings`: تنظیمات برنامه، نام کسب‌وکار، قوانین کارمزد بانکی و رمزهای هش‌شدهٔ محلی.

### ۳. لایهٔ محاسبات و انطباق (CALC / Projections Layer)
- توابع خالص و بدون اثر جانبی (Pure Functions) که داده‌های لایهٔ RAW و MASTER را به خروجی‌های محاسباتی تبدیل می‌کنند:
  - `settleChecksFIFO`: تخصیص ترتیبی و زمانی چک‌ها به فاکتورهای باز، محاسبهٔ اصل بدهی پوشش‌داده‌شده، دیرکرد و مانده.
  - `calculateLateProfit`: محاسبهٔ تصاعدی هزینهٔ دیرکرد بر مبنای فاصلهٔ سررسید تا تاریخ واقعی وصول.
  - `calculateEffectiveProfitForAllocation`: تفکیک سود ظاهری (بهای زمان فروش) و سود مؤثر (بهای آخرین بچ تولید در زمان وصول چک).
  - `reconcileLedgerEvents`: بازسازی ماندهٔ حساب‌ها و موجودی انبارها از روی دفاتر رویداد.
  - `auditDataIntegrity`: ممیزی بلادرنگ شماره‌های تکراری، مراجع شکسته، انحرافات مانده و تخلفات سقف تخصیص.

### ۴. لایهٔ ارائه و تعامل کاربری (APP Layer)
- کامپوننت‌های بصری و کنترل جریان در `client/src/pages/Home.tsx` و `client/src/pages/VendorDirectory.tsx`:
  - برچسب‌گذاری صریح معنایی («فروش · طلب از مشتری»، «خرید · بدهی به تأمین‌کننده»).
  - صفحه‌بندی هوشمند ۲۵ ردیفی جدیدترین‌محور (`desc`).
  - چیدمان‌های بهینه‌سازی‌شده برای دسکتاپ و صفحات لمسی موبایل.
  - استایل‌های مستقل چاپ A4 در دو حالت Portrait و Landscape با پنهان‌سازی ستون‌های محرمانهٔ سود و دیرکرد برای مشتری.

## ۳. معماری ذخیره‌سازی محلی و قرنطینهٔ خطا (Local Storage Architecture)

سیستم از حافظهٔ محلی مرورگر (`localStorage`) به عنوان بانک دادهٔ اولیه استفاده می‌کند:

| کلید ذخیره‌سازی | محتوا و هدف |
|---|---|
| `accounting-workshop-state-v5` | داده‌های اصلی حسابداری، دفاتر رویداد، تنظیمات و اسناد (اسکیما نسخه ۵) |
| `accounting-workshop-vendor-directory-v1` | بانک مستقل استعلام قیمت و فهرست تأمین‌کنندگان بالقوه |
| `accounting-workshop-pwa:restore-snapshots:v1` | حداکثر ۳ نسخهٔ پشتیبان لحظه‌ای خودکار پیش از هر عملیات بازیابی |
| `accounting-workshop-pwa:corrupted-recovery:<timestamp>` | رونوشت قرنطینه در صورت مواجهه با خطای Parse یا مخدوش‌بودن داده‌ها |

### مکانیزم ضد خرابی داده (Fault Tolerance & Storage Recovery)
اگر بارگذاری داده از حافظهٔ محلی به دلیل خاموش شدن ناگهانی مرورگر یا خطای کاربری با شکست مواجه شود:
1. دادهٔ خام اولیه دور ریخته نمی‌شود؛ بلکه فوراً در کلید مستقل قرنطینه ذخیره می‌گردد.
2. وضعیت سیستم با آخرین ساختار پیش‌فرض و ایمن بالا می‌آید تا از توقف کامل برنامه (White Screen of Death) جلوگیری کند.
3. کاربر از طریق پیام‌های سیستمی از وجود داده‌های قرنطینه‌شده آگاه می‌گردد.

## ۴. معماری پیشرو وب (Progressive Web App - PWA)

- **فایل مانیفست (`client/public/manifest.webmanifest`):**
  - تنظیم برای حالت `display: "standalone"` جهت تجربهٔ کاربری شبیه اپلیکیشن بومی.
  - آیکون‌های برداری ماسک‌پذیر ۱۹۲×۱۹۲ و ۵۱۲×۵۱۲.
  - تنظیم جهت پیش‌فرض `orientation: "portrait-primary"`.
  - تنظیم رنگ پوسته `#142d31` و پس‌زمینه `#f7f8fc`.
- **سرویس‌ورکر (`client/public/sw.js`):**
  - نسخهٔ کش جاری: `accounting-workshop-pwa-v4`.
  - استراتژی کش: Network-first برای پیمایش‌ها همراه با Fallback به شل کش‌شدهٔ محلی در حالت آفلاین؛ Cache-first برای assetهای ایستا (آیکون‌ها، مانیفست، اسکریپت‌ها).
  - عدم کش کردن درخواست‌های متفرقه یا داده‌های مالی پویا برای جلوگیری از تداخل امنیتی.

## ۵. پوستهٔ بومی اندروید (Capacitor Android Shell)

- پروژه در مسیر `/android` مجهز به سورس‌های آمادهٔ Gradle و Capacitor برای بسته‌بندی اپلیکیشن اندروید است:
  - نام پکیج: `ir.workshop.accounting`
  - فایل تنظیمات: `capacitor.config.ts` با `webDir: "dist/public"`
  - سیاست عدم اجازه به محتوای مختلط غیرامن (`cleartext: false`).
  - این پوسته به عنوان یک Container پایدار برای بارگذاری دارایی‌های وب عمل می‌کند و موتور محاسباتی مشترک وب را بدون تغییر اجرا می‌نماید.
